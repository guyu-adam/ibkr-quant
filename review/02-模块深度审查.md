# 模块深度审查

## 一、核心模块（core/）

### strategy_base.py ★★★★★ — 优秀

- 36 行，设计干净
- ABC 接口强制 `on_bar` / `on_close` / `name`
- `start()` / `stop()` 提供默认 no-op，可重写
- **无需改进**

### risk.py ★★★★☆ — 良好

- 175 行，分层熔断 + 分数凯利 + 自适应 ATR，体系完整
- **问题**：
  - 类型注解 `float | None` 需 `from __future__ import annotations`（Python 3.9 兼容性）
  - `_check_date_roll()` 中日亏损检查和日内回撤检查逻辑重叠（同一个 `MAX_DAILY_LOSS_PCT` 被检查两次）
  - `kelly_fraction()` 和 `get_atr_multiplier()` 零测试覆盖

### engine.py ★☆☆☆☆ — 不可用

- 157 行，**两个致命导入错误**
- `from core.broker import IBKRBroker` → 应为 `from interfaces.ibkr import IBKRBroker`
- `from strategy.legacy.signals import ...` → 模块不存在（v1 遗留路径）
- `from config.settings import WATCHLIST` → 应为 `US_WATCHLIST`
- **此文件需要完全重写或删除**

### data_feed.py ★★★☆☆ — 可用但有问题

- 192 行，`YFinanceFeed` / `TencentFeed` / `CachedFeed` 三层实现
- **问题**：
  - `YFinanceFeed.fetch_realtime()` 使用 `fast_info` 属性，新版 yfinance 中已废弃
  - `TencentFeed` 依赖腾讯财经非公开 API，字段索引硬编码（`parts[33]`），随时可能失效
  - `from __future__ import annotations` 放在 docstring 之后（应放在文件第一行）

### alpha_factors.py ★★★☆☆ — 功能完整但性能差

- 256 行，42 个因子，6 个类别（动量/波动/成交量/技术/价值/质量）
- **问题**：
  - `_max_drawdown` 用 `rolling().apply()` 在大数据集上极慢
  - `_psar`（抛物线 SAR）纯 Python for 循环，性能差
  - `_zscore` 类型检查过度防御（`hasattr(std, '__len__')`），表明作者对 pandas 行为不确定
  - RSI 计算与 `fast_trading.py`、`regime_detector.py`、`llm_alpha.py` 中的实现重复（4 份拷贝）

### ml_model.py ★★★☆☆ — 可用

- 107 行，LightGBM 回归 + Ridge 回退
- **问题**：
  - `_train_ridge()` 中 `sklearn.linear_model.Ridge` 导入未加 try/except（LightGBM 路径有保护）
  - `select_top()` 在未训练模型上的行为未定义

### ensemble.py ★★★★★ — 优秀

- 81 行，equal / weighted / voting 三种融合方法
- 设计干净，无问题

### meta_labeling.py ★★★☆☆ — 设计好但不够安全

- 95 行，LightGBM 二元分类器过滤交易信号
- **问题**：
  - `filter_signal()` 异常时返回 `True`（fail-open），这是风控组件的危险行为
  - `record_trade()` 维度不匹配时静默丢弃数据

### regime_detector.py ★★★☆☆ — 可用但有隐患

- 102 行，GaussianHMM 三状态市场体制检测
- **问题**：
  - RSI 实现是代码库中的第 3 份拷贝
  - `hmmlearn` 不可用时默认返回 regime 0（trend-up），这是一个隐式的乐观假设
  - `fit_predict()` 在非重训日仍对整个序列做 Viterbi 解码，只取最后一个值，浪费计算

### llm_alpha.py ★★☆☆☆ — 名不副实

- 124 行，"LLM" 名称有误导性——实际是 12 个硬编码模板因子，无任何 LLM API 调用
- RSI 实现是代码库中的第 4 份拷贝
- **建议**：要么接入真实 LLM API，要么改名为 `template_alpha.py`

### transformer_model.py ★★☆☆☆ — 实现有缺陷

- 192 行，Decoder-only Transformer 做多股票收益预测
- **问题**：
  - 使用 `nn.TransformerDecoder` 但 memory 参数填了全零张量——cross-attention 机制没有正确使用
  - 没有 causal mask——训练时模型能看到未来时间步（数据泄露）
  - 无学习率调度、无 early stopping、无梯度裁剪
  - `torch` 导入在 `__init__` 内部，`isinstance` 检查可能不匹配

### walkforward.py ★★★☆☆ — 可用但粗糙

- 125 行，滚动 IS/OOS 窗口 + 参数网格搜索
- **问题**：
  - `_evaluate()` 用 `type()` 动态创建匿名 mock 对象，非常脆弱
  - 评估指标忽略交易成本和滑点
  - 信号记录只取每根 bar 的最后一个信号，不反映持仓周期

### portfolio_optimizer.py ★★★☆☆ — 可用

- 196 行，riskfolio-lib 主路径 + scipy SLSQP 回退
- **问题**：
  - `_riskfolio_optimize` 接受 `min_weight`/`max_weight` 参数但不传给 `rp.Portfolio`
  - `alpha_scores` 为空时静默使用默认值 0.02，可能掩盖数据问题

## 二、策略模块（strategies/）

### fast_trading.py ★★★★☆ — 策略最完整的模块

- 221 行，RSI 均值回归 + HMM 市场体制过滤 + MACD 确认 + 自适应 ATR 止损
- RSI 实现是代码库中的第 5 份拷贝
- `evaluate()` 方法签名与 `on_bar()` 不同，不能用标准引擎驱动
- 直接访问 `RegimeDetector._last_regime` 私有属性

### long_term.py ★★★★☆ — 功能最丰富

- 286 行，HRP 层级风险平价 + Ledoit-Wolf 协方差收缩 + Bootstrap 优化 + DCA + 追踪止损
- **`_in_cluster()` 函数疑似有 bug**（见总体评估第 3 点）
- `LongTermPortfolio.__init__` 签名与 `BaseStrategy` 不一致

### contracts.py ★★★☆☆ — 功能正确但有改进空间

- 138 行，ATR 动态网格 + EMA 趋势过滤 + JSON 状态持久化
- 硬编码 `grid_state.json` 文件名，多实例会冲突
- 价格精度硬编码为 4 位小数，对低价币可能不够精确
- `_calc_atr()` 是简化版，不是标准 True Range 计算

### leverage.py ★★★☆☆ — 配对交易部分实现

- 149 行，协整配对 + 杠杆 ETF 趋势
- `find_cointegrated_pairs` 中 `statsmodels` 导入无 try/except 保护
- Engle-Granger 检验无多重比较校正（多配对时假阳性增加）
- `CointegrationPairStrategy.on_bar()` 总是返回 `[]`，不能通过标准引擎驱动

### options.py ★★☆☆☆ — 三个策略全是 Stub

- 101 行，Covered Call / Protective Put / Iron Condor
- VIX 硬编码为 20.0，`set_vix()` 方法存在但没有任何代码调用
- 所有 `on_bar()` 返回 `[]`，核心逻辑是 `# TODO`
- delta、dte、min_premium 等参数存储了但从未使用

### slow_trading.py ★★☆☆☆ — 两个 Stub

- 80 行，港股 IPO 打新 + ADR 时区套利
- 文档描述了事件驱动逻辑，但 `on_bar()` 全部返回 `[]`
- 无可连接的事件源或调度器

- THS：腾讯财经字段位置硬编码，交易协议未实现
- Schwab：OAuth 2.0 流程未实现，全功能 stub

## 四、模拟交易（paper_trading/）

### engine.py ★★★☆☆ — 功能可用

- `SimulationBroker`：虚拟撮合，含 0.03% 买入/0.13% 卖出费用
- 硬编码 A 股费率，不适用于美股/加密货币
- `positions()` 返回 `{symbol: {shares, avg_cost}}`，与 `RiskManager` 期望的 `{symbol: number}` 不兼容

### app.py ★★☆☆☆ — 极简

- 单页静态 HTML，无动态数据
- `/api/status` 返回硬编码 JSON
- 无 `__main__` 保护，不能独立运行
